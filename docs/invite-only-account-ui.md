# 招待制アカウントUI

この段階は `agent/system-account-edge` を前提とする画面実装です。実Supabaseへのmigration適用、Edge Functionデプロイ、Secret設定、初期システム管理者の登録、Auth設定変更は行いません。

## 利用者の流れ

- ZIP取込みと端末内台帳はログインなしで利用できます。
- クラウド共有を使う利用者は、システム管理者から招待メールを受け取ります。
- 招待リンクを同じブラウザで開き、パスワードを設定するとactiveになります。
- active利用者は、工事を作成するか、工事IDと工事PASS／管理者PASSで既存工事へ入ります。
- システム管理者であっても工事権限は自動付与されません。

自由な新規登録と匿名利用からの自動統合は画面から削除しています。以前の匿名利用者は招待済みアカウントでログインし、工事へ入り直します。

## システム管理画面

DBでactiveなシステム管理者として確認できた場合だけ表示します。表示の有無は利便性のためで、実際の権限判定はEdge FunctionとDBで毎回行います。

- 利用者招待
- Auth作成後にプロフィール保存だけが失敗した招待の安全な復旧
- 招待再送
- 一時停止・再開
- パスワード再設定メール送信
- 削除扱いへの変更
- 管理操作履歴の確認

招待操作は一意な操作IDで冪等化し、Authメタデータ、操作台帳のAuth UUID、メールの非可逆フィンガープリントが一致するときだけ不足プロフィールを補完します。確認できない既存利用者は自動統合せず、復旧対象として表示します。

削除扱いはAuth行や業務履歴を物理削除しません。工事写真・台帳・監査記録を維持したまま、ログインとクラウド操作を拒否します。利用停止は再開できますが、削除扱いは通常画面から再開できません。

## 公開前の適用順

1. `202608180001_system_account_foundation.sql` を安全な検証環境へ適用
2. `202608180002_bootstrap_system_admin.sql` の値をSQL Editor上だけで入力して初期管理者を登録
3. `202608180003_system_account_verification.sql` を実行
4. Edge Functionへ必要なSecretと完全一致のCORS／Redirect URLを設定してデプロイ
5. UIをローカル検証
6. Authの自由な新規登録を停止し、招待・停止・既存JWT拒否を実通信で確認

この順序が完了するまではUIブランチを公開しません。

## ロールバック

UIだけのロールバックは、このブランチのコミットをrevertします。IndexedDBやSupabaseデータの移行はないため、端末データを削除しません。DB rollbackは通常運用では実行せず、基盤資料の厳格な前提を満たす非本番環境だけを対象とします。
